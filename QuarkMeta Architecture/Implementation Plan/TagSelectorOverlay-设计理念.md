# 架构设计决策记录 (ADR)：标签选择浮层的双通道解耦与来源感知提交流程

## 一、设计背景与痛点复盘

在桌面端资产管理系统中，`TagSelectorOverlay`（标签选择浮层）是一个高频复用的公共基础组件，被两个生命周期与物理预期完全不同的场景调用：
1. **`MetaPanel`（元数据属性面板）**：属于“即用即走”的无模态检查器（Inspector），没有“确定/取消”按钮，期望在用户选完标签、浮层失焦关闭时**自动将标签持久化到磁盘与数据库**。
2. **`PresetTagsDialog`（预设自动标签对话框）**：属于具有强事务语义的标准模态对话框，包含明确的**「保存设置」**和**「取消」**按钮，期望浮层关闭仅作为“选择完毕”，**在用户最终点击「保存设置」之前，绝对不能向底层执行任何写盘或数据库操作；点击「取消」必须能完整丢弃全部选择**。

### 历史架构的两大致命硬伤：
* **硬伤 1（实时散弹写盘灾难）**：旧逻辑在浮层中每勾选一个标签就立刻向底层派发落盘指令。底层的 `50ms` 物理防抖定时器远小于人类手指点击间隔（`200ms~500ms`），导致用户连续点选 10 个标签，后台就向机械盘/SSD 连续执行了 10 次 `.QuarkMeta.json` 重写与 20 次 SQLite 写入。
* **硬伤 2（时序与语义冲突）**：若将写盘一刀切延迟至浮层失焦，会导致 `PresetTagsDialog` 的“取消”按钮彻底失效（因为失焦时文件已经被篡改了）；若直接屏蔽信号，又会导致调用方背景界面无法即时看到选中的药丸胶囊（TagPills）。

## 二、核心设计哲学与原则

### 原则 1：双通道信号解耦（展示层与持久层物理隔离）
将 UI 交互的“视觉呈现”与底层存储的“事务提交”完全拆解为两条互不干扰的独立信号总线：

```text
[ 用户在浮层中点击标签 ]
           │
           ├─── 通道一 (实时): emit selectionChanged(...) ──> 仅更新前端 UI 胶囊 (纯内存，0 I/O)
           │
[ 用户完成操作 / 浮层失焦关闭 ]
           │
           └─── 通道二 (提交): emit tagsCommitted(...)    ──> 触发物理原子落盘 (单次 Batch 提交)
```

1. **`selectionChanged(const QStringList& currentSelected)`（观察通道）**：
   - **触发时机**：用户在浮层中**每点击一次**标签即刻发射；
   - **物理契约**：**100% 纯内存流转，严禁调用任何 SQLite 写入、严禁触发任何磁盘 JSON 写盘**；
   - **职责**：仅通知调用方（`MetaPanel` 或 `PresetTagsDialog`）即时刷新界面上的 TagPill 胶囊，让用户立刻看到选中反馈。
2. **`tagsCommitted(const QStringList& finalTags)`（持久化通道）**：
   - **触发时机**：仅在浮层**离场失焦或正常关闭时发射一次**；
   - **物理契约**：携带最终确定的标签全集，作为**单次原子提交**的唯一入口。

---

### 原则 2：来源感知契约驱动（TagTriggerSource）
浮层本身不再“盲目写盘”，而是通过注入**触发源枚举**明确感知自己的调用上下文，实行差异化的生命周期策略：

```cpp
enum class TagTriggerSource {
    MetaPanel,         // 场景 A：失焦即提交
    PresetTagsDialog   // 场景 B：失焦不落盘，提交权移交外部对话框
};
```

## 三、业务调用矩阵与数据流向对账

| 业务维度 | 场景 A：来自 `MetaPanel`（属性面板） | 场景 B：来自 `PresetTagsDialog`（预设对话框） |
| :--- | :--- | :--- |
| **浮层实例化** | 传入 `TagTriggerSource::MetaPanel` | 传入 `TagTriggerSource::PresetTagsDialog` |
| **点选标签时** | 触发 `selectionChanged` ➔ **面板药丸即时点亮** | 触发 `selectionChanged` ➔ **弹窗药丸即时点亮** |
| **点选时 I/O 开销**| **0 次写盘，0 次 SQLite 访问** | **0 次写盘，0 次 SQLite 访问** |
| **浮层失焦/关闭时**| **发射 `tagsCommitted`** ➔ 计算增删差集 ➔ 向 `CoreEngine` 派发任务，**单次落盘** | **不发射 `tagsCommitted`**，静默销毁浮层，数据保留在弹窗内存列表 |
| **用户点击「取消」**| （不涉及取消按钮，失焦即确定） | **内存丢弃，底层数据库与文件 100% 原封不动** |
| **用户点击「保存」**| （不涉及） | **由弹窗的 `onSaveClicked` 单次原子持久化落盘** |

## 四、时序因果链详解

### 链路 A：`MetaPanel`（元数据属性面板）
1. **唤起**：用户在属性面板点击“添加标签”，创建浮层，绑定 `TagTriggerSource::MetaPanel`；
2. **交互**：用户连续点选 5 个标签、取消 2 个标签：
   - 每次点击仅在内存中增删 `m_selectedTags`；
   - 发射 `selectionChanged`，`MetaPanel` 收到后实时重绘药丸（视觉零延迟）；
   - **期间写盘次数 = 0**；
3. **收敛**：用户点击空白区域，浮层失焦触发 `closeOverlay()`：
   - 检查来源为 `MetaPanel`，发射 `tagsCommitted(finalTags)`；
   - `MetaPanel` 将最终结果与打开前的初始快照做一次 `Diff` 计算；
   - 一次性向 `CoreEngine` 派发新增与移除任务，**整批操作仅触发一次合并落盘**。

### 链路 B：`PresetTagsDialog`（预设自动标签）
1. **唤起**：用户右键分类点击“设置预设标签”，在弹窗中点击标签区，创建浮层，绑定 `TagTriggerSource::PresetTagsDialog`；
2. **交互**：用户在浮层中点选标签：
   - 每次点击发射 `selectionChanged`，弹窗背后的药丸实时跟随增减；
   - **期间写盘次数 = 0**；
3. **收敛**：用户点空白处浮层关闭：
   - 检查来源为 `PresetTagsDialog`，**压制 `tagsCommitted`，绝不写盘**；
   - 最终标签暂存在对话框的 `m_presetTags` 内存成员中；
4. **终局判定**：
   - 若用户点击**「取消」**：对话框 `reject()` 退出，刚才选的所有标签随内存释放全部抛弃，文件与数据库彻底免受污染；
   - 若用户点击**「保存设置」**：在 `onSaveClicked()` 中一次性写入 `LibraryDao::updatePresetTags`，并单次调用 `CoreEngine` 完成关联文件同步。

## 五、架构收益总结

1. **绝对消除 I/O 散弹风暴**：将原本随点击线性增长的 `O(N)` 次写盘彻底压缩为常数级 `O(1)`，彻底拔除了 50ms 伪防抖导致的并发磁盘争用；
2. **前端交互零延迟**：纯内存信号保证了 UI 响应速度达到纳秒级，点击标签无任何掉帧；
3. **业务语义严格吻合**：彻底解决了模态对话框与非模态属性面板之间的语义冲突，保证了“取消”操作的绝对可靠性与数据一致性（SSOT）。
