addStretch(1) 加的是 QVBoxLayout 自己的一个"弹性空白占位"（QSpacerItem），它根本不是一个控件（没有对应的 QObject/QWidget）。 内容少的时候，这块弹性空白会被撑开去填满 m_containerWidget 剩余的可视高度——你截图里看到的那片"空白"，物理上就是这块 spacer，鼠标点在上面，事件的实际接收者是它背后露出来的 m_containerWidget（一个啥都没做的空白widget），跟 m_fileView 毫无关系。这就是为什么从这片空白往上拖拽框选完全没反应，而在条目本身所在的行（还在 m_fileView 真实边界内）左右拖拽却可以。

根治方案：不用独立的弹性占位，让 m_fileView 自己占满剩余空间
不能简单粗暴地把 m_fileView 换成"给它stretch因子"了事——因为它现在的高度是靠 setFixedHeight(jv->totalHeight()) 精确卡死在"内容真实高度"上的（这是为了保证文件多的时候能正确撑高触发外层滚动）。如果单纯改成 stretch，文件多的时候反而会失效。

正确做法是：m_fileView 的高度 = max(内容真实高度, 画布剩余可视空间)——内容少时，让它自己撑满剩下的空白（这样空白区域就真正属于它了）；内容多时，还是按真实内容高度撑高触发外层滚动，两者不冲突。

int SectionedScrollCanvas::computeFileViewMinHeight() const {
    int used = 0;
    if (m_folderHeader && m_folderHeader->isVisible()) used += m_folderHeader->height();
    if (m_folderView && m_folderView->isVisible()) used += m_folderView->height();
    if (m_fileHeader && m_fileHeader->isVisible()) used += m_fileHeader->height();
    return qMax(0, viewport()->height() - used);
}
