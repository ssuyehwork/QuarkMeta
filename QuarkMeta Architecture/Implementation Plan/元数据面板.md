### 一、 事实：打开一个文件夹时的标准数据加载流水线

当用户切换或打开一个新目录（例如 `D:\素材库`，里面有 1,000 张图片）时，正规的时序只有严格的 **3 步**：

```
                           【打开文件夹时的标准时序流水线】

   [ 用户进入 D:\素材库 ]
             │
             ▼ (在后台扫描线程中执行)
   ┌─────────────────────────────────────────────────────────────────────────────┐
   │ 第 1 步：一次性将 D:\素材库\.QuarkMeta.json 整包读入内存 (Single-Pass Load) │
   │ • 耗时仅 1~2ms：整目录的星级、颜色、标签、备注、宽高一次性全部解入内存 Map  │
   └─────────────────────────────────────┬───────────────────────────────────────┘
                                         │
                                         ▼
   ┌─────────────────────────────────────────────────────────────────────────────┐
   │ 第 2 步：扫描物理文件的同时，在内存中完成 O(1) 属性快速装配 (Meta Decorate) │
   │ • 遍历文件时，直接从第 1 步加载好的内存 Map 中提取属性装配给 ItemRecord     │
```

### 二、 推断：为什么“先读进内存”是唯一正确的架构？（因果链路）

- **[推断 1 - 将 1000 次磁盘 I/O 压缩为仅仅 1 次]**
  - **原因**：一个目录下无论有 10 个文件还是 10,000 个文件，元数据全部紧凑保存在该目录唯一的 `.QuarkMeta.json` 中。
  - **影响**：进入目录瞬间只打开这 1 个文件读取 1 次，所有的标签、颜色、备注就全部在内存里了。
  - **结果**：消灭了在用户浏览、点击、框选、修改时对硬盘进行的成千上万次重复磁盘寻道，性能达到极限。

- **[推断 2 - 彻底消灭“读脏数据”与“时序竞态”]**
  - **原因**：所有元数据在进入目录时就已经常驻在内存 `MetaMemoryCache` 中。
  - **影响**：用户做任何修改（例如点击绿色），系统优先更新内存。
  - **结果**：Model 和 View 永远从内存拿数据，无论硬盘是慢速机械盘还是网络 NAS，界面看到的永远是 100% 准确、最新的数据，绝不会发生“改了绿色又从硬盘读出旧紫色”的荒谬现象。
