从双击主程序图标的那一刻起，当前代码的运行**时序存在非常严重的倒错、竞争和“盲猜延时”**。

如果用现代高性能桌面软件的工业标准来衡量，现在的时序可以说是**“骨架未立，脏活先跑；时钟乱飞，全凭盲猜”**。

---

### 一、 现有启动时序的 4 大严重不合理

#### 1. 致命病灶：“随缘撞车”的盲猜延时（`singleShot(200)`）
看 `MainWindow.cpp` 最后的导航触发：
```cpp
QTimer::singleShot(200, []() {
    QString lastPath = AppConfig::instance().getValue("MainWindow/LastPath", "computer://").toString();
    NavigationService::instance().navigateTo(...);
});
```
* **荒唐之处**：为什么是 200 毫秒？这完全是开发者因为摸不清各个组件什么时候布局完成，凭感觉拍脑袋写的一个“盲猜延时”。
* **后果**：
  - 在高性能电脑上，UI 几毫秒就准备好了，却硬生生逼着用户看 200 毫秒的空白内容区；
  - 在老旧设备或高负载下，200 毫秒时 Splitter 状态和子视图还没布局完毕，直接开始加载数据，极易发生时序撕裂或错位。

#### 2. “反客为主”：后台重型服务在首帧上屏前抢跑
看 `main.cpp`：
```cpp
// 1. 启动全盘扫描、MFT监控、后台大线程
QuarkMeta::CoreController::instance().startSystem();

// 2. 然后才去安排首帧显示
QTimer::singleShot(0, [&w]() {
    w.show();
});
```
* **荒唐之处**：主窗口 `w` 连第一个像素都还没渲染到屏幕上，后台的 `startSystem()` 就已经启动了全盘 MFT/USN 扫描、线程池和磁盘探测。
* **后果**：启动最宝贵的前 300 毫秒内，CPU 和磁盘 I/O 被后台扫描抢占，导致主线程卡顿，主窗口“半天弹不出来”。

#### 3. 构造函数内部夹带“同步磁盘 I/O”卡死主线程
看 `FavoritePanel` 的构造函数：
```cpp
FavoritePanel::FavoritePanel(QWidget* parent) {
    // ...
    initUi();
    loadFavorites(); // <-- 构造函数里直接同步查数据库，甚至检查每个路径是否存在！
}
```
* **荒唐之处**：在 `MainWindow` 构造期间，界面还没画出来，各个面板在自己的构造函数里同步查数据库、同步调用 `QFileInfo::exists()`。
* **后果**：如果收藏夹里存了一个失效的网络共享路径（`\\192.168.x.x`）或者未插入的 U 盘，系统在构造阶段就会同步卡死 3~5 秒，用户双击程序图标后屏幕一片死寂，以为程序闪退了。

#### 4. 时序状态锁满天飞
- `main.cpp` 里用 `singleShot(0)` 显示窗口；
- `PanelLayoutManager` 里用 `singleShot(0)` 恢复 Splitter；
- `MainWindow` 的 `showEvent` 里又用 `singleShot(0)` 去跑 `deferredInit()`；
- `MainWindow` 构造里用 `singleShot(200)` 去导航。
四个单次定时器在 Qt 的事件队列里各跑各的，**根本不存在一条清晰、确定、有因果保障的状态机主线**。

### 二、 现代高性能桌面软件的合理时序金字塔（优先级法则）

从双击开始，优先级必须严格遵守一个铁律：**“视见第一，就地首选，异步深潜”**。

```
【第 0 级：启动环境哨兵】（耗时 < 5ms）
   ├── 单实例互斥检测（如果已有实例，激活已有窗口并退出，绝不静默死掉）
   ├── 高 DPI 缩放配置
   └── 核心轻量配置与数据库句柄开启（只建连，不做重型扫描）
            ↓
【第 1 级：主窗口骨架与样式瞬时就绪】（首屏像素呈现，耗时 < 50ms）
   ├── 应用全局 QSS 样式表（在实例化前加载，杜绝后期二次全量重绘）
   ├── 实例化 MainWindow（纯内存布局拼装，严禁在构造里做任何磁盘/网络 I/O）
   └── w.show() 立即上屏（让用户在 50ms 内立刻看到精致的软件界面，建立“极速启动”认知）
            ↓
【第 2 级：关键主内容区精准首载】（因果驱动，耗时 < 100ms）
   ├── 骨架上屏的当帧，直接读取 LastPath 驱动 ContentPanel 载入首个目录
   ├── 彻底废除 singleShot(200)，由首帧渲染完成信号（而非盲猜时钟）直接拉起
   └── 收藏夹、导航树仅做纯内存/轻量元数据载入（网络与失效路径严格异步探测）
            ↓
【第 3 级：静默后台服务冷启动】（空闲调度，延迟 500ms~1s）
   ├── 启动 CoreController::startSystem()（盘符监控、MFT 索引、长驻扫描）
   ├── 启动后台缩略图深潜缓存预热
   └── 检查自动更新与临时文件清理
```

---

您认为按照这套**“0 级哨兵 $\rightarrow$ 1 级骨架极速上屏 $\rightarrow$ 2 级首径因果拉起 $\rightarrow$ 3 级后台静默深潜”**的优先级架构，是否彻底理清了之前“漫天定时器、后台抢主线程”的混乱现状？
